# 결재첨부용 이관신청서 — 화면/출력 설계안 v0.1

## 1. 설계 목적

이관신청서는 단순한 기계 연계용 데이터 파일이 아니다.

학교 등 생산기관에서 내부결재를 받을 때 결재자가 다음을 **눈으로 확인하고 판단할 수 있는 첨부문서**여야 한다.

- 어떤 기록물을 이관하는가
- 얼마나 많은가
- 보존기간은 어떻게 구성되는가
- 공개/비공개 상태는 어떠한가
- 특수기록물이 포함되어 있는가
- 분권 결과가 자연스러운가
- 검토가 필요한 예외가 있는가

동시에 같은 데이터를 이후 기록물관리 자동화가 그대로 이어받아야 한다.

따라서 출력은 한 데이터에서 두 표현으로 만든다.

```text
문서등록대장
      ↓
편철·분류·검증
      ↓
Canonical Transfer Dataset
      ├─ [사람용] 결재첨부용 이관신청서.xlsx
      └─ [시스템용] 관리연계 데이터(JSON/내부데이터)
```

두 결과는 같은 원천에서 생성하므로 서로 내용이 어긋나지 않아야 한다.

---

## 2. 출력 원칙

### 원칙 A — 표준양식을 변경하지 않는다

기록연구사가 제시한 표준양식의 필드·열 구조는 그대로 유지한다.

프로그램 편의를 위해 공식 열을 추가하거나 순서를 바꾸지 않는다.

### 원칙 B — 판단용 정보는 별도 '검토요약'으로 제공한다

공식 표준 이관신청서에 없는 요약정보는 별도 시트로 제공한다.

권장 Excel 시트 순서:

```text
1. 검토요약
2. 이관신청서
3. 세부색인            (필요 시)
4. 데이터검증          (오류/경고가 있을 때만)
5. _연계데이터         (숨김 또는 별도 파일 권장)
```

최종 배포 정책에 따라 3~5번은 조정할 수 있지만,
**이관신청서 시트 자체는 표준양식 그대로 유지**한다.

### 원칙 C — 결재자가 봐야 할 정보와 시스템 정보는 분리한다

결재자는 표준 시스템 코드나 원본 행번호를 볼 필요가 없다.

예:
- `creatOrgNm`, `openDivNm` 같은 시스템코드 → 화면에서 숨김
- 문서번호 목록, 원본 행번호 → 시스템 추적용
- 기록물명, 보존기간, 권수, 공개구분 → 결재자가 보는 정보

# 4. 화면 1 — 편철 결과 검토

이 화면은 실무자가 결과를 수정하는 작업화면이다.

## 상단 요약

```text
기관          천안버들유치원
처리부서      행정실
대상 문서     307건
이관 대상     286건
제외          21건
편철 결과     72권
총 쪽수       6,842쪽
검토 필요     3건
```

※ 수치는 실제 실행결과에서 계산한다.

## 권 단위 카드/표

권 하나를 다음처럼 표현한다.

```text
[12권] 학교회계 세출관리 (3-2)

생산연도      2025
단위과제      학교회계 세출관리
보존기간      5년
기록유형      문서류 > 일반문서 > 종이
공개구분      부분공개 (6호)
문서수        8건
쪽수          94쪽

[세부문서 보기] [앞 권과 합치기] [여기서 분권] [제외]
```

## 표시색의 의미

색상 자체에만 의존하지 않고 아이콘/문구를 함께 사용한다.

- 정상: 별도 경고 없음
- 확인 필요: `검토 필요`
- 특수기록물: `도면`, `사진`, `영상`, `음성` 등의 배지
- 비공개 포함: `부분공개/비공개` 배지
- 수동수정: `사용자 수정` 표시
- 자동분권: `자동 분권` 표시

# 6. 검토요약 시트 상세 설계

## 6.1 기본정보 영역

표시 항목:

- 기관명
- 내부 처리부서
- 이관연도
- 작성일
- 담당자/인계자 (정책 확정 후)
- 대상 자료 기준연도

## 6.2 전체 규모

표시 항목:

- 원본 문서 건수
- 이관대상 문서 건수
- 제외 문서 건수
- 최종 기록물철/권 수
- 총 쪽수
- 특수기록물 권 수
- 검토필요 권 수

## 6.3 보존기간 요약

보존기간별 권수와 비율을 표로 보여준다.

예:

| 보존기간 | 권수 | 비율 |
|---|---:|---:|
| 3년 | 2 | 2.8% |
| 5년 | 21 | 29.2% |
| 10년 | 18 | 25.0% |
| 30년 | 12 | 16.7% |
| 준영구 | 9 | 12.5% |
| 영구 | 10 | 13.8% |

## 6.4 공개구분 요약

- 공개
- 부분공개
- 비공개

부분공개/비공개 권은 비공개호수까지 상세목록에서 확인할 수 있게 한다.

## 6.5 기록유형 요약

표준 3단 분류 기준으로 표시한다.

예:

```text
문서류
  ├ 일반문서 58권
  ├ 대장      5권
  ├ 카드      2권
  └ 도면      2권

시청각류
  ├ 사진      4권
  ├ 영상      1권
  └ 음성      0권
```

## 6.6 검토 필요 사항

오류와 경고를 구분한다.

### 오류
최종 출력 전에 반드시 해결

예:
- 단위과제 미매칭
- 보존기간 미확정
- 기록물 유형 미확정
- 필수 기관명 누락
- 이관대상 권인데 제목 없음

### 경고
출력 가능하지만 확인 권장

예:
- 100쪽 초과 수동편철
- 특수기록물
- 부분공개/비공개 포함
- 표준 단위과제와 원본 보존기한 불일치
- 사용자가 자동분류를 수정
- 권에 서로 다른 생산연도가 존재

# 7. 공식 이관신청서 시트

표준양식 구조를 그대로 사용한다.

프로그램은 공식 표 내부 값만 채운다.

## 결재자가 바로 볼 수 있어야 하는 주요 값

권장 표시 우선순위:

1. 기록물철 제목
2. 생산연도
3. 단위과제
4. 보존기간
5. 기록유형
6. 세부유형
7. 매체유형
8. 수량(권)
9. 공개구분
10. 비공개호수
11. 필요 시 내부 처리부서/인계자

시스템 내부 코드나 원본 행번호는 표시하지 않는다.

## 표의 시각 원칙

표준서식이 허용하는 범위 안에서:

- 헤더 고정
- 인쇄 제목행 반복
- 행 높이 통일
- 기록물철 제목은 줄바꿈
- 숫자/연도는 가운데 정렬
- 제목/단위과제는 왼쪽 정렬
- 공개구분은 문자 그대로 표시
- 비공개호수는 별도 필드 사용
- 페이지 하단에 페이지번호 표시

표준서식 자체의 서식규칙이 존재할 경우 그 규칙을 우선한다.

# 8. 세부색인 시트

공식 이관신청서만으로는 한 권 안에 어떤 문서가 들어 있는지 알기 어렵다.

따라서 결재자가 필요할 때 확인할 수 있도록 **세부색인**을 선택적으로 붙인다.

권장 열:

| 권 | 문서번호 | 등록일자 | 문서제목 | 쪽수 | 공개구분 | 비공개호수 |
|---|---|---|---|---:|---|---|

각 권 앞에 기록물철 제목을 구분행으로 넣을 수 있다.

### 용도

- 기록물철 제목이 적절한지 확인
- 공개/비공개 집계 근거 확인
- 분권 결과 확인
- 특정 문서가 어느 권에 들어갔는지 확인

단, 결재문서가 지나치게 커질 경우 웹에서만 열람하고 Excel 첨부에는 제외할 수 있도록 옵션화한다.

---

# 9. 데이터검증 시트

오류나 경고가 있는 경우에만 생성하는 것이 좋다.

예:

| 수준 | 권 | 항목 | 내용 | 처리 |
|---|---|---|---|---|
| 경고 | 12 | 공개구분 | 비공개 문서 포함 | 부분공개로 집계 |
| 경고 | 18 | 기록유형 | 제목 키워드로 도면 추정 | 사용자 확인완료 |
| 오류 | 21 | 단위과제 | 표준 단위과제 매칭 실패 | 미해결 |

**오류가 남아 있으면 최종 결재파일 생성 버튼을 비활성화**하는 방향을 기본으로 한다.

# 11. 결재용 파일과 관리연계 데이터의 관계

## 사람용

`기록물이관신청서_천안버들유치원_2026.xlsx`

예:
```text
검토요약
이관신청서
세부색인
```

## 시스템용

브라우저 내부에서는 별도의 Canonical Dataset으로 유지한다.

외부 파일이 필요할 경우:

`기록물이관데이터_천안버들유치원_2026.json`

또는 향후 관리 앱이 같은 웹 프로젝트 안에서 직접 읽을 수 있다면 JSON 다운로드 자체를 생략할 수도 있다.

---

# 12. 동일 데이터 원칙

결재용 이관신청서와 관리연계 데이터는 **별도로 계산하면 안 된다.**

반드시 다음과 같이 한다.

```text
Canonical RecordFolder[]
        │
        ├→ renderApprovalWorkbook()
        │
        └→ handoffToManagement()
```

따라서 결재가 끝난 이관신청서와 기록물관리대장에 들어간 자료가 서로 다를 가능성을 구조적으로 줄인다.

---

# 13. 결재 후 변경관리

내부결재 이후 자료가 변경되면 두 데이터가 달라질 수 있다.

따라서 최종 생성 시 다음 메타정보를 함께 기록하는 것을 권장한다.

- 생성일시
- 데이터 버전
- 기관명
- 이관연도
- 총 권수
- 데이터 지문(hash) 또는 내부 작업 ID

결재 이후 관리단계에서 이관자료를 불러올 때 같은 작업본인지 확인할 수 있다.

사용자에게 hash를 보여줄 필요는 없지만 내부 검증용으로 활용할 수 있다.

---

# 14. 사용성 원칙

이 도구의 목표는 사용자가 표준데이터 구조를 공부하게 하는 것이 아니다.

일반 사용자는 다음 흐름이면 충분해야 한다.

```text
문서등록대장 올리기
      ↓
자동편철 결과 확인
      ↓
필요한 항목 몇 개 수정
      ↓
결재자료 미리보기
      ↓
[이관신청서 만들기]
```

표준 시스템코드, JSON, 필드매핑 등은 일반 사용자 화면에서 최대한 숨긴다.

---

# 15. 현재 확정안

결재용 출력의 기본 구성은 다음으로 한다.

1. **검토요약** — 결재자가 규모·구성·특이사항 판단
2. **표준 이관신청서** — 공식 첨부서식
3. **세부색인** — 권별 원본 문서 근거, 선택 포함
4. **데이터검증** — 오류/경고가 있을 때 선택 포함
5. **관리연계 데이터** — 사람용 문서와 분리, 동일 Canonical Dataset에서 생성

이 구조를 기본안으로 삼고 실제 표준 이관신청서 양식을 확인한 뒤 셀 단위 출력설계를 확정한다.

## 16. 프로젝트 핵심 우선순위 확정

사용자 업무 관점에서 두 자동화의 핵심은 다음과 같이 정의한다.

### 이관신청 자동화의 핵심

**편철 자동화가 핵심 기능이다.**

결재첨부용 이관신청서는 편철 결과를 사람이 확인하고 내부결재를 받을 수 있는 문서 표현이다.

기본 출력 구조:
1. 이관신청 정보 — 기관명, 생산부서, 작성자(인계자), 학교 기록물관리자, 이관연도
2. 이관목록 — 편철 자동화로 생성된 기록물철/권 목록
3. 세부색인 — 각 권의 원본 문서 근거
4. 검토사항 — 예외만 보조적으로 표시

따라서 '검토요약 대시보드'를 결재문서의 중심으로 두지 않는다.

### 기록물관리 자동화의 핵심

**보존상자 자동 집계·배정이 핵심 기능이다.**

표준 이관자료를 받아 보존기간, 쪽수, 권수 등의 규칙으로 상자를 구성하고 관리번호 및 위치정보를 추가하여 최종 관리대장에 통합한다.

두 프로그램은 각각의 핵심을 단순하게 유지한다.

```text
이관신청 = 문서들을 올바르게 편철한다
기록물관리 = 편철된 기록물철을 올바르게 상자에 담는다
```
