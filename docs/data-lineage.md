# 데이터 계보(Data Lineage) — 문서등록대장 → 이관 → 기록물관리대장

## 1. 이 문서의 목적

이 프로젝트의 시작점은 최종 기록물관리대장이 아니라 **K-에듀파인 문서등록대장**이다.

따라서 표준 기록물관리대장의 각 항목을 다음과 같이 구분한다.

- **SOURCE**: 문서등록대장에서 직접 얻을 수 있음
- **REFERENCE**: 표준 기준표/기관코드표를 이용해 자동 산출 가능
- **TRANSFER**: 이관신청 자동화에서 편철·집계하면서 생성 가능
- **CONTEXT**: 기관명, 이관연도 등 한 번 입력하거나 실행환경에서 확정
- **MANAGEMENT**: 기록관이 인수·검수·배치한 뒤에야 생기는 정보
- **SYSTEM**: 외부 시스템/DB에서 부여되는 값 또는 현재 출처 불명
- **POLICY**: 자동화 규칙을 기록연구사와 확정해야 하는 값

핵심 원칙은 **아직 존재하지 않는 값을 억지로 채우지 않는 것**이다.

---

## 2. 실제 시작 파일: 문서등록대장

현재 예시 문서등록대장에는 다음 20개 열이 있다.

1. 문서번호
2. 결재유형
3. 제목
4. 기안(접수)자
5. 결재권자
6. 등록일자
7. 수신(발신)자
8. 처리상태
9. 게시여부
10. 연계유형
11. 전자비전자구분
12. 공개구분
13. 공개제한근거
14. 첨부파일여부
15. 쪽수
16. 목록공개여부
17. 과제명
18. 과제카드명
19. 보존기한
20. 최초발송일자

예시 파일은 307건이며 문서번호 접두부는 모두 같은 기관명으로 확인되었다.

### 단위과제 자동매핑 검증

예시 307건을 표준 학교 단위과제표와 비교한 결과:

- 과제카드명만으로 직접 매핑: **296건**
- 중복 후보를 과제명으로 해소: **2건**
- 과제카드명이 표준표에 직접 없어서 과제명으로 보완: **9건**
- 최종 미매핑: **0건**
- 표준 단위과제의 보존기간과 문서등록대장의 보존기한 불일치: **0건**

따라서 현재 예시 기준으로 **단위과제와 보존기간은 높은 신뢰도로 자동화 가능**하다.

## 3. 업무 단계

```text
[0] 문서등록대장
      문서 단위 원천데이터
            ↓
[1] 이관신청 자동화
      편철 / 권 분리 / 집계 / 보완
            ↓
[2] 표준 이관자료
      기록물철(권) 단위 메타데이터
            ↓
[3] 기록관 인수·검수·배치
      상자 / 위치 / 상태 / 등록정보 추가
            ↓
[4] 표준 기록물관리대장
```

문서등록대장은 **문서 단위**, 표준 기록물관리대장은 **기록물철 또는 권 단위**이므로 중간의 편철 단계가 필수다.

## 5. 이관신청서가 책임져야 할 범위

이관신청 자동화가 최종 관리대장의 모든 값을 만들 필요는 없다.

### 이관 단계에서 확정 가능한 핵심 메타데이터

- 생산기관
- 생산연도 시작/끝
- 기록물명
- 단위과제
- 보존기간
- 기록유형
- 세부유형
- 매체유형
- 수량(권)
- 공개구분
- 비공개호수
- 이관연도
- 필요 시 관리번호(정책 확정 후)

### 기록관에서 추가할 정보

- 기록관 물리적 위치
- 보존상자
- 기록물 상태
- 등록자
- DB등록여부
- 처리과 위치정보가 필요한 경우 해당 값
- 열람구분 등 기록관 정책 항목

따라서 **표준 이관자료는 표준관리대장의 완성본이 아니라, 관리대장으로 승격 가능한 중간 데이터**로 정의한다.

## 6. 자동으로 채울 수 없는 항목에 대한 처리 원칙

### A. 아직 업무상 존재하지 않는 값
예: 서고·서가·상자·기록물상태

→ 이관신청서에서는 **빈 값으로 유지**하고 기록물관리 자동화에서 채운다.

### B. 원천자료에 없지만 실행 컨텍스트로 알 수 있는 값
예: 생산기관, 이관연도

→ 프로그램에서 자동 추정하고 사용자가 한 번 확인한다.

### C. 규칙을 정하면 자동 산출 가능한 값
예: 단위과제, 보존기간, 공개구분 집계

→ 표준 규칙으로 자동 계산하되 검증 결과를 보여준다.

### D. 원천자료만으로는 의미를 확정할 수 없는 값
예: 기록유형·세부유형·매체유형·열람구분

→ 무리하게 추정하지 않고 **추천 + 사용자 확인** 또는 기록연구사 정책을 적용한다.

### E. 외부 시스템이 부여하는 값
예: 기록물철ID 가능성

→ 출처를 확인하기 전에는 임의 생성하지 않는다.

---

## 7. 바로 확정해야 할 정책 항목

1. **관리번호(mngNo)의 부여 시점과 형식**
2. **처리부서명(keepOrgNm)의 의미**
   - 학교가 이관할 때 생산기관과 동일하게 유지할지
   - 기록관 인수 후 현 관리부서를 의미하게 할지
3. **열람구분(operReadRangeNm)의 결정 규칙**
4. **공개구분을 문서 단위에서 기록물철 단위로 집계하는 규칙**
5. **기록유형/세부유형/매체유형의 자동추천 범위**
6. **기록물철ID(folderId)의 실제 부여 주체**
7. **처리과 위치번호/상자번호를 신규 이관자료에서 요구할지**

이 7개가 확정되면 문서등록대장에서 표준 이관자료까지의 데이터 규격을 거의 고정할 수 있다.
