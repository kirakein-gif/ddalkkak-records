# 문서등록대장 → 이관신청서 → 표준 기록물관리대장 필수 전달정보 v0.1

## 1. 목적

이관신청서는 단순한 결재용 출력물이 아니라,
**문서등록대장의 정보를 편철 단위로 재구성하여 표준 기록물관리대장까지 손실 없이 전달하는 중간 기록**이어야 한다.

따라서 이관신청서 설계 전에 먼저 다음을 확정한다.

1. 문서등록대장에서 직접 가져오는 정보
2. 이관신청 단계에서 반드시 계산·보완해야 하는 정보
3. 최종 관리대장에는 직접 표시되지 않아도 관리 자동화에 필요한 추적정보
4. 기록물관리 단계에서 새로 생성해야 하는 정보

---

## 2. 전체 흐름

```text
문서등록대장
  문서 단위 원천자료
      ↓
이관신청 자동화
  편철 / 분권 / 표준화 / 검증
      ↓
이관신청서
  결재문서 + 필수 전달데이터
      ↓
기록물관리 자동화
  상자집계 / 관리번호 / 위치 / 상태
      ↓
표준 기록물관리대장
```

핵심은 **이관신청서 단계에서 최종 관리대장에 필요한 '내용 메타데이터'를 최대한 확정해 두고,
기록물관리 단계에서는 '관리 메타데이터'만 추가하는 것**이다.

---

## 3. 이관신청서에 반드시 존재해야 하는 정보

### A. 최종 관리대장으로 직접 이어지는 필수 필드

| 의미 | 이관신청 단계에서의 처리 | 최종 표준관리대장 |
|---|---|---|
| 기관명 | 기관 컨텍스트로 확정 | keepOrgNm / creatOrgNm 계열 |
| 생산연도 시작 | 편철된 문서 중 최소 등록연도 | creatYyyyFrom |
| 생산연도 종료 | 편철된 문서 중 최대 등록연도 | creatYyyyTo |
| 기록물철 제목 | 편철 결과로 생성·사용자 확인 | title |
| 표준 단위과제 | 과제카드명 + 과제명으로 표준화 | clssNm |
| 보존기간 | 표준 단위과제표 기준으로 확정 | presvTermNm |
| 기록유형 | 자동추천 + 사용자확인 | typeDivNm |
| 세부유형 | 자동추천 + 사용자확인 | detailTypeNm |
| 매체유형 | 자동추천 + 사용자확인 | mediaTypeNm |
| 수량(권) | 편철/분권 결과 | hoCnt |
| 공개구분 | 권 내부 문서 공개정보 집계 | openDivNm |
| 비공개호수 | 공개제한근거 중복제거·정렬 | openGrade |
| 이관연도 | 이관 작업 컨텍스트 | takeYyyy |

이 항목들은 **이관신청서가 기록물관리대장으로 넘어가기 전에 반드시 확정되어 있어야 한다.**

단, `전자비전자구분` 자체는 전달필드가 아니다. 이 업무의 편철 대상은 전부 비전자 기록물이므로 업로드 검증에만 사용한다.

---

## 4. 표준관리대장에는 직접 안 보여도 반드시 함께 넘겨야 하는 정보

이 정보가 빠지면 기록물관리 자동화의 상자집계·중복검증·추적성이 약해진다.

| 내부 전달필드 | 이유 |
|---|---|
| sheetCount | 상자당 1000매 기준 자동집계에 필요 |
| sourceDocumentNos[] | 중복검증 및 원본문서 추적 |
| sourceTaskCard | 편철 근거와 단위과제 매핑 검증 |
| sourceTaskName | 표준 단위과제 보조매핑 근거 |
| sourceRowRefs[] | 원본 CSV 어느 행에서 왔는지 추적 |
| documentCount | 한 권에 몇 개 문서가 포함됐는지 확인 |
| userAdjusted | 사용자가 자동결과를 수정했는지 확인 |
| splitReason / splitFlag | 자동분권·수동분권 여부 추적 |
| validationState | 미해결 오류가 있는지 관리단계에서 확인 |
| transferPackageId | 같은 이관신청서 재업로드 중복 방지 |
| rowId | 한 이관묶음 안에서 각 기록물철 식별 |

이 값들은 사람이 보는 이관신청서 본문에 모두 표시할 필요는 없지만
**같은 Excel 파일 안의 숨김 연계시트에 반드시 유지**한다.

---

## 5. 결재문서로서 반드시 필요한 업무정보

이 정보는 관리대장 필드와 직접 1:1 대응하지 않을 수 있지만,
내부결재와 인계·인수 책임성을 위해 이관신청서에 필요하다.

- 기관명
- 내부 처리부서
- 작성자 / 인계자
- 학교 기록물관리자
- 작성일
- 이관연도
- 전체 이관 권수
- 필요 시 전체 문서건수 / 총 쪽수
- 이관목록

이 항목은 사람용 이관신청서 시트에 표시한다.

## 6. 기록물관리 단계에서 새로 생성해야 하는 정보

다음 정보는 문서등록대장이나 이관신청서의 결손이 아니라
**기록물관리 업무를 수행하면서 새로 생기는 데이터**다.

| 관리단계 필드 | 생성 이유 |
|---|---|
| 관리번호 | 기관별 자체 관리번호 부여 |
| 보존상자번호 / 상자명 | 상자 자동집계 결과 |
| 서고 | 실물 배치 |
| 서가 | 실물 배치 |
| 열 | 실물 배치 |
| 층 | 실물 배치 |
| 위치번호 | 기관별 위치관리 |
| 기록물상태 | 실물 검수 후 판단 |
| DB등록여부 | 실제 DB 등록 후 |
| 등록자 | 최종 관리대장 등록 담당자 의미로 정책 확정 필요 |

따라서 **이관신청서에서 이 값을 미리 만들지 않는다.**

## 7. 이관신청서에서 누락되면 안 되는 핵심 3종

### ① 최종대장 필수 메타데이터
최종 관리대장에 직접 들어갈 정보.

예:
기록물철 제목, 생산연도, 단위과제, 보존기간, 기록유형, 공개구분

### ② 관리자동화용 계산정보
최종 대장에는 안 보여도 상자 자동집계에 필요한 정보.

예:
총 쪽수(sheetCount), 문서건수

### ③ 추적정보
나중에 오류가 났을 때 원본문서까지 돌아가기 위한 정보.

예:
sourceDocumentNos, sourceTaskCard, sourceRowRefs, transferPackageId

이 세 묶음이 모두 있어야
**이관신청서 하나만으로 기록물관리대장 자동화가 안정적으로 이어질 수 있다.**

## 8. 이상적인 이관신청서 Excel 구조

```text
기록물이관신청서.xlsx
├─ 이관신청서
│   ├ 기관/작성자/기록물관리자
│   └ 기록물철 이관목록
│
├─ 세부색인
│   └ 각 기록물철에 포함된 원본문서 목록
│
└─ _handoff (숨김)
    ├ 최종관리대장 필수 메타데이터
    ├ 상자집계용 sheetCount
    ├ 원본문서 추적정보
    ├ 검증상태
    └ 패키지/행 식별자
```

검토요약과 검토사항은 선택 보조시트로 둘 수 있다.

---

## 9. 기록물관리 자동화가 이관신청서를 받았을 때

기록물관리 프로그램은 다음을 수행한다.

1. _handoff 시트의 규격버전 확인
2. 필수 전달필드 누락 검사
3. transferPackageId 중복 확인
4. 여러 기관 이관신청서 통합
5. 보존기간·생산연도·쪽수 기준으로 상자 자동집계
6. 기관별 관리번호 부여
7. 물리적 위치·상태 등 관리정보 추가
8. 표준 기록물관리대장 출력

즉 **기록물관리 자동화는 이관신청서의 편철결과를 재계산하지 않는다.**
학교에서 결재받은 편철결과를 그대로 받아 관리작업만 수행한다.

---

## 10. 프로젝트의 핵심 경계

### 이관신청 자동화가 책임질 것

- 문서단위 원천자료를 기록물철 단위로 편철
- 표준 단위과제와 보존기간 확정
- 기록유형/세부유형/매체유형 확정
- 공개구분/비공개호수 집계
- 권별 쪽수·문서수 계산
- 원본문서 추적정보 유지
- 사람이 결재할 수 있는 이관신청서 생성

### 기록물관리 자동화가 책임질 것

- 여러 이관신청서 취합
- 상자 자동집계
- 관리번호 부여
- 물리적 위치정보 추가
- 기록물상태/DB등록여부 등 관리정보 추가
- 표준 기록물관리대장 완성

## 11. 설계 기준

앞으로 이관신청서 양식이나 UI를 바꿀 때는 항상 다음 질문을 먼저 확인한다.

> "이 정보가 빠져도 최종 표준 기록물관리대장을 정확히 만들 수 있는가?"

대답이 '아니오'이면
그 정보는 **보이는 이관신청서 또는 숨김 연계데이터 중 반드시 한 곳에 남겨야 한다.**

이 규칙을 문서등록대장 → 이관신청서 → 기록물관리대장 전체 설계의 최우선 기준으로 삼는다.


## 12. 비전자 업무전제

- 편철 대상 기록물은 전부 비전자이다.
- `전자비전자구분`은 이관신청서/관리대장 연계값이 아니라 입력검증값이다.
- 일반문서는 `문서류 → 일반문서 → 종이`를 기본 추천할 수 있다.
- 사진·도면·필름·DVD 등은 비전자라도 매체가 종이가 아닐 수 있으므로 별도 유형/매체 확인을 유지한다.
