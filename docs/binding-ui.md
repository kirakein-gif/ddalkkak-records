# 웹 편철 UI 설계안 v0.2

## 1. 설계 목표

사용자군은 크게 두 가지다.

### 일반 사용자
- 1년치 비전자 기록물이 많지 않음
- **편철 작업은 반드시 수행함**
- 다만 문서 수가 적어 한 화면에서 전체 편철안을 빠르게 확인·조정할 수 있음
- 복잡한 대량편철 도구까지 항상 노출할 필요는 없음

### 대량 사용자
- 회계 등 특정 업무 담당자
- 동일/유사 과제카드의 문서가 많음
- 100쪽 기준 분권이 반복 발생
- 문서 하나씩 수동조작하면 비효율적

따라서 UI는 두 개의 별도 프로그램으로 나누지 않고,
**하나의 화면이 데이터량에 따라 자연스럽게 단순/상세하게 동작하는 적응형 구조**로 한다.

---

## 2. 기본 사용자 흐름

```text
문서등록대장 업로드
    ↓
자동분석
    ↓
편철안 자동 제시
    ↓
사용자 편철 작업
    ├─ 자동제시안 그대로 사용
    ├─ 문서 제외/이동
    ├─ 분권/합권
    └─ 기록유형 등 보정
    ↓
편철 확정
    ↓
이관신청서 생성
```

핵심은 **모든 사용자가 편철 작업을 하되, 프로그램이 먼저 편철안을 제시하여 처음부터 수작업하지 않게 하는 것**이다.

---

## 3. 첫 화면 — 자동분석 결과

업로드 직후 다음만 보여준다.

```text
문서등록대장 분석 완료

전체 문서        307건
편철 제안          219권
검토 필요          12권
특수기록물           4권
보존기간 불일치       0건

[편철 시작]
[전체 편철안 보기]
```

모든 사용자는 이 단계 다음에 편철 작업화면으로 들어간다. 다만 문서가 적으면 전체 편철안이 한 화면에 들어오므로 빠르게 확인하고 확정할 수 있다.

---

## 4. 편철 검토 화면의 기본 구조

### 좌측 — 과제카드/업무 묶음 목록

예:

```text
전체
검토 필요  3

학교회계 세출관리        84건 · 12권
급여관리                 21건 · 3권
복무관리                  8건 · 1권
공문서등록                 4건 · 1권
...
```

- 문서 수
- 편철된 권 수
- 검토 필요 여부
- 특수기록물 포함 여부

를 함께 보여준다.

과제카드가 많은 경우 검색 가능.

---

## 5. 가운데 — 선택 과제카드의 원본문서

한 과제카드를 선택하면 해당 문서만 표시한다.

권장 열:

- 체크
- 등록일자
- 문서번호
- 제목
- 쪽수
- 공개구분
- 현재 편철권
- 검토상태

예:

```text
학교회계 세출관리

현재 84건 / 12권 / 923쪽

[1권] 94쪽
  01. 지출결의서 ...        23쪽
  02. 계약관련 서류 ...     41쪽
  03. 물품구입 ...           30쪽

-------------------- 자동 분권선 --------------------

[2권] 88쪽
  ...
```

문서를 일반 테이블로만 보여주지 않고
**권 경계가 시각적으로 명확해야 한다.**

---

## 6. 우측 — 편철 결과 요약

선택한 과제카드의 현재 결과를 카드 형태로 표시한다.

```text
1권   94쪽   3문서   정상
2권   88쪽   5문서   정상
3권  132쪽   1문서   확인필요
4권   75쪽   4문서   정상
...
```

각 권 카드에서:

- 문서수
- 총 쪽수
- 생산연도
- 공개구분
- 기록유형
- 검토상태

를 확인할 수 있다.

---

## 7. 사용자가 실제로 하는 조작

문서를 자유 드래그앤드롭하는 기능은 보조로 두고
주요 조작은 단순 버튼으로 한다.

### 문서 행 조작
- 이관 제외
- 위/아래 이동
- 여기서 새 권 시작
- 앞 권으로 이동
- 다음 권으로 이동

### 권 단위 조작
- 앞 권과 합치기
- 이 권부터 다시 자동분권
- 기록유형 일괄변경
- 공개구분 검토
- 편철 확정

### 다중 선택
회계 담당자용으로 여러 문서를 체크한 후:
- 선택문서 제외
- 선택문서 한 권으로 묶기
- 선택지점에서 분권
- 기록유형 일괄지정

---

## 8. 일반 사용자의 편철 화면

일반 사용자도 편철 작업은 반드시 수행한다.

다만 문서 수가 적으므로 같은 편철 화면을 **간결한 형태**로 보여준다.

예:

```text
편철 작업

전체 15건 → 현재 4권

[1권] 복무관리                    82쪽
  01. 복무관련 문서               32쪽
  02. 근무상황 관련 문서          50쪽
  ─────────────────────────

[2권] 개인정보보호                67쪽
  01. 개인정보 관련 문서          67쪽
  ─────────────────────────

[3권] 안전관리                    91쪽
  ...

[4권] 시설관리                    44쪽
  ...

[편철 확정]
```

사용자는 이 화면에서:

- 문서가 올바른 과제카드에 묶였는지
- 기록물철 제목이 적절한지
- 분권 위치가 맞는지
- 제외할 문서가 있는지
- 기록유형이 맞는지

를 확인한다.

문서 수가 적기 때문에 **모든 권을 눈으로 확인하는 것이 부담스럽지 않도록 한 화면에 최대한 펼쳐 보여주는 방식**이 적합하다.

즉 일반 사용자는 편철을 생략하는 것이 아니라,
**편철 작업량이 적어서 단순한 UI로 빠르게 끝나는 것**이다.

---

## 9. 회계 등 대량 사용자의 편철 화면

회계 담당자도 동일한 편철 작업을 수행하지만
문서량이 많으므로 같은 화면에 대량작업 기능을 추가로 노출한다.

 회계 등 대량 사용자를 위한 상세모드

문서수가 많거나 자동분권이 많이 발생하면
편철 검토화면을 자동으로 제안한다.

예:

```text
학교회계 관련 문서가 126건 있습니다.
자동으로 18권으로 편철했습니다.

다음 5권은 확인이 필요합니다.
- 100쪽을 초과한 단일문서 2권
- 생산연도 혼재 1권
- 사용자 확인이 필요한 유형 2권

[확인 필요한 5권만 검토]
[18권 전체 검토]
```

회계 담당자는 모든 편철결과를 검토하되, 과제카드·권 단위 접기/펼치기와 일괄작업으로 많은 문서를 효율적으로 확인한다.

---

## 10. 대량 편철의 핵심 기능

### 10.1 과제카드별 접기/펼치기
모든 문서를 한 표에 펼치지 않는다.

### 10.2 권 경계선
100쪽 기준으로 자동생성된 경계를 명확하게 보여준다.

### 10.3 누적 쪽수
문서 옆에 현재 권 누적 쪽수를 표시한다.

예:
```text
32쪽   누적 32
41쪽   누적 73
22쪽   누적 95
18쪽   → 다음 권
```

### 10.4 재분권
문서 순서를 바꾸거나 제외한 후
`이 지점부터 다시 자동편철` 버튼 제공.

### 10.5 권 단위/과제카드 단위 확정
회계처럼 권 수가 많을 때는 확인한 권 또는 과제카드 묶음을 한 번에 확정할 수 있다.

단, 전체 편철이 끝났다는 최종 확정은 사용자가 직접 수행한다.

---

## 11. 검토필요 판단

자동편철 후 다음 경우만 사용자에게 적극적으로 보여준다.

### 필수 확인
- 표준 단위과제 미매칭
- 보존기간 미확정/불일치
- 기록유형 미확정
- 매체유형 미확정
- 제목 없음

### 확인 권장
- 단일문서 100쪽 초과
- 서로 다른 생산연도 혼재
- 부분공개/비공개 문서 포함
- 특수기록물
- 자동분류를 사용자가 수정한 권

### 정상
- 모든 필수값 확정
- 자동편철 기준 충족

UI는 전체 편철구조를 보여주되 **예외자료가 눈에 잘 띄도록 강조**한다. 일반 사용자도 전체 편철을 확인할 수 있어야 한다.

## 12. 문서량에 따른 UI 밀도 변화

모든 사용자는 **동일한 편철 작업화면**을 사용한다.

차이는 편철 자체의 유무가 아니라 화면의 정보 밀도와 대량도구 노출이다.

### 소량
문서 30건 이하 또는 권 10권 이하

- 과제카드와 권을 기본 펼침
- 원본문서가 바로 보임
- 대량선택 도구 최소화
- 한 화면에서 전체 편철 확인 가능

### 중량
문서 31~100건

- 과제카드별 접기/펼치기
- 권 단위 요약 제공
- 다중선택 기능 제공

### 대량
문서 100건 초과 또는 한 과제카드 30건 이상

- 과제카드 목록 패널
- 검색/필터
- 권 단위 일괄확정
- 다중문서 이동/제외
- 선택지점 이후 재분권
- 대량 편철 상태 요약

이 기준값은 실제 사용 테스트 후 조정한다.

## 13. 웹 편철화면의 핵심 레이아웃

데스크톱 기준:

```text
┌──────────────────────────────────────────────────────────────┐
│ 편철 검토             전체 307건 · 219권 · 검토필요 12권   │
├──────────────┬──────────────────────────────┬───────────────┤
│ 과제카드     │ 문서 / 권 경계               │ 편철 결과     │
│              │                              │               │
│ 회계 84건    │ [1권 94쪽]                   │ 1권  정상     │
│ 급여 21건    │ 문서1 23쪽 · 누적23           │ 2권  정상     │
│ 복무 8건     │ 문서2 41쪽 · 누적64           │ 3권  확인     │
│ ...          │ 문서3 30쪽 · 누적94           │ ...           │
│              │ -------- 새 권 --------       │               │
│              │ [2권 88쪽]                   │               │
├──────────────┴──────────────────────────────┴───────────────┤
│ [자동편철 다시] [선택 제외]             [편철 확정]        │
└──────────────────────────────────────────────────────────────┘
```

일반 사용자도 이 편철 화면을 사용한다. 문서가 적을 때는 좌·우 보조패널을 단순화하고 전체 권을 펼친 형태로 보여준다.

## 14. 모바일보다 데스크톱 우선

이 업무는 Excel 파일 업로드와 많은 표 검토가 핵심이므로
모바일 최적화보다 **PC 브라우저 1080p 업무환경**을 우선한다.

다만 화면 폭이 좁으면:
- 좌측 과제카드 패널 접기
- 우측 편철결과 패널 접기
가 가능하게 한다.

---

## 15. 이 UI와 최종 데이터의 관계

사용자가 UI에서 수행하는 모든 변경은
RecordFolder와 source mapping에 즉시 반영한다.

예:
- 문서 제외
- 문서 순서 변경
- 수동분권
- 권 합치기
- 기록유형 수정

이 변경결과가 그대로:
1. 결재용 이관신청서
2. 세부색인
3. _handoff
에 동시에 반영되어야 한다.

---

## 16. 핵심 UX 원칙

> 프로그램은 편철안을 먼저 제시하고,
> 사용자가 실제 편철을 검토·조정하여 확정한다.

모든 사용자가 편철을 수행한다. 일반 사용자는 적은 문서를 한 화면에서 빠르게 편철하고, 회계 담당자는 같은 원칙 위에서 과제카드·권 단위 대량도구를 사용한다.
