# 웹 편철 UI 설계안 v0.1

## 1. 설계 목표

사용자군은 크게 두 가지다.

### 일반 사용자
- 1년치 비전자 기록물이 많지 않음
- 자동편철 결과가 대부분 그대로 사용 가능
- 복잡한 편철 UI가 오히려 부담

### 대량 사용자
- 회계 등 특정 업무 담당자
- 동일/유사 과제카드의 문서가 많음
- 100쪽 기준 분권이 반복 발생
- 문서 하나씩 수동조작하면 비효율적

따라서 UI는 두 개의 별도 프로그램으로 나누지 않고,
**하나의 화면이 데이터량에 따라 자연스럽게 단순/상세하게 동작하는 적응형 구조**로 한다.

---

## 2. 기본 사용자 흐름

```text
문서등록대장 업로드
    ↓
자동분석
    ↓
자동편철
    ↓
편철 결과 검토
    ├─ 이상 없음 → 바로 확정
    └─ 확인 필요 → 해당 과제카드만 상세검토
    ↓
이관신청서 생성
```

핵심은 **모든 문서를 사용자가 직접 편철하지 않게 하는 것**이다.

---

## 3. 첫 화면 — 자동분석 결과

업로드 직후 다음만 보여준다.

```text
문서등록대장 분석 완료

전체 문서        307건
자동편철 결과     219권
검토 필요          12권
특수기록물           4권
보존기간 불일치       0건

[검토 필요한 것만 보기]       [전체 편철결과 보기]
                         [편철 확정]
```

일반 사용자는 검토 필요가 0~몇 건이면
전체 200행짜리 표를 볼 필요가 없다.

---

## 4. 편철 검토 화면의 기본 구조

### 좌측 — 과제카드/업무 묶음 목록

예:

```text
전체
검토 필요  3

학교회계 세출관리        84건 · 12권
급여관리                 21건 · 3권
복무관리                  8건 · 1권
공문서등록                 4건 · 1권
...
```

- 문서 수
- 편철된 권 수
- 검토 필요 여부
- 특수기록물 포함 여부

를 함께 보여준다.

과제카드가 많은 경우 검색 가능.

---

## 5. 가운데 — 선택 과제카드의 원본문서

한 과제카드를 선택하면 해당 문서만 표시한다.

권장 열:

- 체크
- 등록일자
- 문서번호
- 제목
- 쪽수
- 공개구분
- 현재 편철권
- 검토상태

예:

```text
학교회계 세출관리

현재 84건 / 12권 / 923쪽

[1권] 94쪽
  01. 지출결의서 ...        23쪽
  02. 계약관련 서류 ...     41쪽
  03. 물품구입 ...           30쪽

-------------------- 자동 분권선 --------------------

[2권] 88쪽
  ...
```

문서를 일반 테이블로만 보여주지 않고
**권 경계가 시각적으로 명확해야 한다.**

---

## 6. 우측 — 편철 결과 요약

선택한 과제카드의 현재 결과를 카드 형태로 표시한다.

```text
1권   94쪽   3문서   정상
2권   88쪽   5문서   정상
3권  132쪽   1문서   확인필요
4권   75쪽   4문서   정상
...
```

각 권 카드에서:

- 문서수
- 총 쪽수
- 생산연도
- 공개구분
- 기록유형
- 검토상태

를 확인할 수 있다.

---

## 7. 사용자가 실제로 하는 조작

문서를 자유 드래그앤드롭하는 기능은 보조로 두고
주요 조작은 단순 버튼으로 한다.

### 문서 행 조작
- 이관 제외
- 위/아래 이동
- 여기서 새 권 시작
- 앞 권으로 이동
- 다음 권으로 이동

### 권 단위 조작
- 앞 권과 합치기
- 이 권부터 다시 자동분권
- 기록유형 일괄변경
- 공개구분 검토
- 편철 확정

### 다중 선택
회계 담당자용으로 여러 문서를 체크한 후:
- 선택문서 제외
- 선택문서 한 권으로 묶기
- 선택지점에서 분권
- 기록유형 일괄지정

---

## 8. 일반 사용자를 위한 단순모드

별도의 '모드 선택' 화면을 강요하지 않는다.

자동편철 결과가 단순하면 프로그램이 기본적으로 다음처럼 보인다.

```text
자동편철 완료

15건 → 4권

✓ 검토 필요한 항목이 없습니다.

[편철결과 간단히 보기]
[이관신청서 만들기]
```

사용자가 `편철결과 간단히 보기`를 눌렀을 때만
상세 편철화면을 연다.

즉 일반 사용자는 **업로드 → 결과확인 → 이관신청서** 세 단계로 끝날 수 있다.

---

## 9. 회계 등 대량 사용자를 위한 상세모드

문서수가 많거나 자동분권이 많이 발생하면
편철 검토화면을 자동으로 제안한다.

예:

```text
학교회계 관련 문서가 126건 있습니다.
자동으로 18권으로 편철했습니다.

다음 5권은 확인이 필요합니다.
- 100쪽을 초과한 단일문서 2권
- 생산연도 혼재 1권
- 사용자 확인이 필요한 유형 2권

[확인 필요한 5권만 검토]
[18권 전체 검토]
```

회계 담당자도 정상 13권을 하나씩 클릭할 필요가 없다.

## 10. 대량 편철의 핵심 기능

### 10.1 과제카드별 접기/펼치기
모든 문서를 한 표에 펼치지 않는다.

### 10.2 권 경계선
100쪽 기준으로 자동생성된 경계를 명확하게 보여준다.

### 10.3 누적 쪽수
문서 옆에 현재 권 누적 쪽수를 표시한다.

예:
```text
32쪽   누적 32
41쪽   누적 73
22쪽   누적 95
18쪽   → 다음 권
```

### 10.4 재분권
문서 순서를 바꾸거나 제외한 후
`이 지점부터 다시 자동편철` 버튼 제공.

### 10.5 정상권 일괄확정
검토경고가 없는 권은 한 번에 확정 가능.

---

## 11. 검토필요 판단

자동편철 후 다음 경우만 사용자에게 적극적으로 보여준다.

### 필수 확인
- 표준 단위과제 미매칭
- 보존기간 미확정/불일치
- 기록유형 미확정
- 매체유형 미확정
- 제목 없음

### 확인 권장
- 단일문서 100쪽 초과
- 서로 다른 생산연도 혼재
- 부분공개/비공개 문서 포함
- 특수기록물
- 자동분류를 사용자가 수정한 권

### 정상
- 모든 필수값 확정
- 자동편철 기준 충족

UI의 기본 화면은 **정상 자료가 아니라 예외자료를 중심으로 보여준다.**

---

## 12. 문서량에 따른 자동 UI 변화

예시 기준:

### 소량
문서 30건 이하 또는 권 10권 이하
→ 간단 결과화면 우선

### 중량
문서 31~100건
→ 과제카드별 접힌 목록 제공

### 대량
문서 100건 초과 또는 한 과제카드 30건 이상
→ 편철 검토화면 진입을 권장하고 대량도구 노출

이 수치는 테스트 후 조정한다.

## 13. 웹 편철화면의 핵심 레이아웃

데스크톱 기준:

```text
┌──────────────────────────────────────────────────────────────┐
│ 편철 검토             전체 307건 · 219권 · 검토필요 12권   │
├──────────────┬──────────────────────────────┬───────────────┤
│ 과제카드     │ 문서 / 권 경계               │ 편철 결과     │
│              │                              │               │
│ 회계 84건    │ [1권 94쪽]                   │ 1권  정상     │
│ 급여 21건    │ 문서1 23쪽 · 누적23           │ 2권  정상     │
│ 복무 8건     │ 문서2 41쪽 · 누적64           │ 3권  확인     │
│ ...          │ 문서3 30쪽 · 누적94           │ ...           │
│              │ -------- 새 권 --------       │               │
│              │ [2권 88쪽]                   │               │
├──────────────┴──────────────────────────────┴───────────────┤
│ [자동편철 다시] [선택 제외]             [편철 확정]        │
└──────────────────────────────────────────────────────────────┘
```

일반 사용자는 이 화면에 들어오지 않고 끝낼 수도 있다.

## 14. 모바일보다 데스크톱 우선

이 업무는 Excel 파일 업로드와 많은 표 검토가 핵심이므로
모바일 최적화보다 **PC 브라우저 1080p 업무환경**을 우선한다.

다만 화면 폭이 좁으면:
- 좌측 과제카드 패널 접기
- 우측 편철결과 패널 접기
가 가능하게 한다.

---

## 15. 이 UI와 최종 데이터의 관계

사용자가 UI에서 수행하는 모든 변경은
RecordFolder와 source mapping에 즉시 반영한다.

예:
- 문서 제외
- 문서 순서 변경
- 수동분권
- 권 합치기
- 기록유형 수정

이 변경결과가 그대로:
1. 결재용 이관신청서
2. 세부색인
3. _handoff
에 동시에 반영되어야 한다.

---

## 16. 핵심 UX 원칙

> 사용자가 편철을 하는 것이 아니라,
> 프로그램이 편철하고 사용자는 틀린 것만 고친다.

일반 사용자는 거의 손대지 않아도 되고,
회계 담당자는 대량자료도 과제카드 단위·권 단위로 빠르게 검토할 수 있게 한다.
