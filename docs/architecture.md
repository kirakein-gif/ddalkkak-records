# 전체 아키텍처 초안

## 목적

이 프로젝트는 기록물 업무를 세 개의 독립 프로그램으로 나누되, 내부적으로는 하나의 표준 데이터 모델과 공통 엔진을 사용한다.

## 업무 흐름

### 1. transfer — 이관신청 자동화

K-에듀파인 문서등록대장(CSV 등)을 입력받아 편철·분류·검토를 거쳐 표준 이관자료를 생성한다.

### 2. management — 기록물관리 자동화

여러 기관이 제출한 표준 이관자료를 받아 검토하고, 보존상자를 구성하며, 스티커·상자표지 등을 만들고 최종적으로 표준 기록물관리대장에 통합한다.

### 3. migration — 기존대장 표준전환

지역별·기관별로 서로 다른 기존 기록물관리대장을 분석하고 표준 필드에 매핑한다. 관리자가 자동매핑 결과를 수정한 뒤 변환 프로필(JSON)을 저장·배포할 수 있게 한다.

## 공통 계층

```text
입력 Excel/CSV
     ↓
parser
     ↓
표준 내부 데이터
     ↓
validator / transform
     ↓
┌──────────────┬──────────────┬──────────────┐
│ transfer     │ management   │ migration    │
└──────────────┴──────────────┴──────────────┘
     ↓
exporter
     ↓
표준 Excel
```

## 개발 원칙

1. Excel 열 위치를 업무 로직의 기준으로 삼지 않는다.
2. 업무 로직은 표준 필드 코드에 대해 동작한다.
3. 학교/직속/기록관 차이는 표준 스키마와 출력 템플릿으로 관리한다.
4. 지역별 과거 양식 차이는 migration profile(JSON)로 격리한다.
5. 파일은 가능한 한 브라우저 내부에서 처리한다.
6. 실제 기록물 데이터는 저장소에 포함하지 않는다.

> 이 문서는 초기 설계안이며 실제 표준서식 분석 후 계속 갱신한다.
