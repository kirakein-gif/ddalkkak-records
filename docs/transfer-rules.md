# 이관신청 자동화 — 현행 VBA 업무규칙 분석

## 목적

기존 `기록물이관신청서 자동화_v20`의 VBA를 기준으로 웹버전에서 유지해야 할 업무규칙과 수정해야 할 한계를 정리한다.

## 1. 입력

K-에듀파인 문서등록대장에서 현재 VBA가 읽는 열:

- 문서번호
- 결재유형
- 과제카드명
- 제목
- 등록일자
- 쪽수
- 공개구분
- 공개제한근거
- 보존기한
- 과제명
- 수신(발신)자

현재 원본에 존재하지만 VBA가 읽지 않는 주요 열:

- 전자비전자구분
- 목록공개여부
- 첨부파일여부

예시 문서등록대장은 307건 모두 `비전자`다. 웹버전에서는 `전자비전자구분`을 반드시 읽어 입력자료가 이관 대상 업무에 맞는지 검증하는 것이 안전하다.

## 2. 문서종류 자동분류

제목 키워드 기준으로 1차 분류한다.

| 키워드 | 현행 분류 |
|---|---|
| 도면 | 도면류 |
| 녹음, 음반, DVD, 영화, 비디오, 테이프 | 녹음·동영상류 |
| 필름, 사진, 그림, 인화, 슬라이드, CD | 사진·필름류 |
| 카드 | 카드류 |
| 그 외 | 일반문서 |

사용자가 드롭다운에서 직접 수정할 수 있다.

### 표준서식 전환 시 주의

표준관리대장은 다음 3단 구조를 사용한다.

- 기록유형: 문서류 / 시청각류
- 세부유형: 일반문서·대장·카드·도면 / 사진·영상·음성
- 매체유형: 종이, 필름, 사진CD, DVD 등

따라서 기존의 `문서종류` 1개 필드를 그대로 표준 `detailTypeNm`에 넣으면 안 된다. 웹버전에서는 3개 필드로 분해해야 한다.

특히 현행 분류에는 표준 세부유형인 **대장**이 별도로 없으며, 녹음·동영상도 표준에서는 **음성/영상**으로 나뉜다.

## 3. 편철 정렬

현행 정렬 순서:

1. 과제카드명
2. 일반문서 여부 — 일반문서가 먼저
3. 문서종류 — 같은 특수유형끼리 묶음
4. 등록일자

## 4. 권 구성

기준 최대 쪽수: **100쪽**

- 이관대상이 아닌 행은 권 계산에서 제외
- 과제카드가 바뀌면 새 권 시작
- 일반문서가 아닌 기록물은 쪽수와 관계없이 **항상 독립된 1권**
- 일반문서는 누적 쪽수가 100쪽을 초과하면 다음 권
- 사용자가 `분권`을 지정하면 강제로 다음 권 시작
- 사용자가 이관대상에서 제외/복원 가능
- 행 순서 수동조정 가능
- 행 이동은 같은 과제카드 경계 안에서만 가능

즉 편철의 기본 단위는 **과제카드 × 권**이다.

## 5. 이관신청서 한 행의 생성

한 권당 한 행을 만든다.

현재 생성값:

- 생산부서: 사용자가 입력한 처리과/부서명
- 기록물형태: 문서종류
- 시작연도: 권의 첫 문서 등록연도
- 종료연도: 권의 첫 문서 등록연도
- 보존기간: 첫 문서의 보존기한
- 보존기간 만료연도: 종료연도 + 보존연수
- 기록물철 제목
- 표준화 단위과제: 원본 `과제명`
- 수량: 1
- 공개여부: 권에 포함된 문서의 공개정보 집계
- 문서등록번호: 권에 문서가 1건일 때만 표시
- 숨김 보조값: 권 전체 쪽수

### 기록물철 제목

```text
과제카드명 (총권수-권차)
: 첫 문서 제목 외 N건
```

총 권수가 두 자리 이상이면 권차를 0으로 채운다.

예:
- 7권: `7-1`
- 12권: `12-01`

## 6. 공개정보 집계

현행 규칙:

- 제한 문서가 하나도 없으면 → `공개`
- 공개 문서와 제한 문서가 섞이면 → `부분공개`
- 모두 `비공개`면 → `비공개`
- 제한 상태가 혼재하면 → `부분공개`
- 공개제한근거는 중복 제거 후 호수 순서로 정렬해 붙임

예:
`부분공개(5호, 6호, 7호)`

웹버전에서는 출력 시
- `openDivNm` = 공개/부분공개/비공개
- `openGrade` = 5, 6, 7호
로 분리 저장한다.

## 7. 현행 코드에서 바로잡을 부분

### 생산연도 시작/끝

현재는 시작연도와 종료연도를 모두 **첫 문서의 등록연도**로 기록한다.

웹버전에서는 권 전체 문서의 등록일자를 기준으로:
- 시작연도 = 최소 연도
- 종료연도 = 최대 연도
로 계산해야 한다.

### 단위과제

현재 이관신청서는 원본 `과제명`을 사용한다.

예시 307건을 표준 학교 단위과제표와 비교한 결과:
- 과제카드명 직접 매칭 296건
- 과제명 보조로 최종 매칭 11건
- 최종 미매핑 0건
- 보존기간 불일치 0건

웹버전은 `과제카드명`을 1차 키, `과제명`을 보조키로 사용하여 **표준 단위과제(clssNm)** 를 확정한다.

### 기관과 내부 부서 분리

현재 이관신청서의 처리과 입력값(예: 행정실)은 업무상 필요한 정보이지만, 표준관리대장의 `creatOrgNm/keepOrgNm`은 기관코드 조회 대상이다.

따라서 내부 모델에서 반드시 분리한다.

- `institutionName`: 천안버들유치원 등 기관
- `departmentName`: 행정실 등 내부 처리과

내부 부서명을 표준 기관명 필드에 직접 넣지 않는다.

## 8. 웹버전에서 유지할 사용자 보정 기능

- 문서종류/표준 기록유형 보정
- 이관대상 제외/복원
- 같은 과제카드 내 순서 이동
- 강제 분권
- 편철 결과 권 단위 미리보기
- 최종 이관신청서 생성 전 검증
