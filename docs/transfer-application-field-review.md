# 이관신청서 필드 재설계 검토 v0.1

## 결론

기존 이관신청서 표시양식을 그대로 유지하는 것만으로는 표준 기록물관리대장과 안정적으로 연결하기에 부족하다.

다만 문서등록대장의 20개 열을 모두 이관신청서로 가져올 필요도 없다.

가장 이상적인 구조는 다음과 같다.

1. 문서등록대장에서 최종대장 생성에 필요한 원천필드만 읽는다.
2. 편철 과정에서 기록물철 단위 메타데이터를 완성한다.
3. 사람이 보는 이관신청서에는 결재·검토에 필요한 핵심 필드만 표시한다.
4. 전체 원본문서 추적정보와 상자집계용 데이터는 같은 Excel의 숨김 handoff에 보존한다.
5. 기록물관리 자동화는 handoff를 읽어 관리번호·상자·위치 등 관리단계 필드만 추가한다.

---

## 1. 기존 이관신청서 표시필드

기존 양식의 이관목록:

- 일련번호
- 생산부서
- 기록물형태
- 시작연도
- 종료연도
- 보존기간
- 보존기간 만료연도
- 기록물철 제목
- 표준화 단위과제
- 수량
- 공개여부
- 문서등록대장 문서등록번호

상단에는 처리과명, 이관연도, 인계자, 인수자가 있다.

---

## 2. 기존 양식에서 부족한 핵심

### 기록물형태 1개 → 표준 3개 필드로 분리

표준관리대장은 다음을 별도 관리한다.

- 기록유형
- 세부유형
- 매체유형

따라서 기존 '기록물형태' 한 열만으로는 부족하다.

### 공개여부 → 공개구분 + 비공개호수 분리

표준관리대장은 공개구분과 비공개호수를 별도 필드로 요구한다.

### 기관명과 내부부서 분리

기존 '생산부서/처리과'가 행정실 같은 내부부서를 뜻한다면,
표준관리대장의 생산부서명/처리부서명(기관코드 조회 대상)과 같은 의미로 사용하면 안 된다.

따라서:

- 생산기관 전체명 / 기관코드
- 내부 처리부서명

을 별도 보존한다.

### 문서등록번호 1개는 다문서 편철에 부적합

한 기록물철에 여러 문서가 들어가면 단일 문서등록번호 열은 완전한 추적정보가 될 수 없다.

사람용 목록에서는 문서수와 쪽수를 표시하고,
전체 문서번호 목록은 세부색인 또는 handoff에 저장하는 것이 적합하다.

## 3. 권장 결재용 이관신청서 목록 필드

상단 메타정보:

- 생산기관
- 내부 처리부서
- 이관연도
- 작성자/인계자
- 학교 기록물관리자
- 필요 시 인수자
- 총 기록물철 수 / 총 쪽수

본문 이관목록 권장열:

| 항목 | 이유 |

| 기록물철 제목 | 표준대장 직접연계 |
| 표준 단위과제 | 표준대장 직접연계 |
| 보존기간 | 표준대장 직접연계 |
| 기록유형 | 표준대장 직접연계 |
| 세부유형 | 표준대장 직접연계 |
| 매체유형 | 표준대장 직접연계 |
| 수량(권) | 표준대장 직접연계 |

## 4. 기존 필드 중 재검토할 항목

### 보존기간 만료연도

표준관리대장 직접 필드는 아니다.

종료연도와 보존기간으로 산출 가능한 값이므로
핵심 연계데이터에서는 저장하지 않아도 된다.

업무상 눈으로 확인할 가치가 있다면 결재용 표시값으로만 계산해서 보여줄 수 있다.

### 문서등록대장 문서등록번호

다문서 편철에서는 1개 셀로 표현하기 어렵다.

따라서 본문에서는 '문서수'로 대체하고,
전체 번호는 세부색인 및 handoff에 저장하는 방향을 권장한다.

---

## 5. 문서등록대장에서 반드시 읽을 필드

최종 관리대장까지 연결하기 위해 핵심적으로 필요한 원천필드:

| 원천필드 | 용도 |
|---|---|
| 문서번호 | 원본문서 추적 / 중복검증 |
| 제목 | 편철·기록물철 제목 생성 |
| 등록일자 | 생산연도 시작/끝 |
| 전자비전자구분 | 업로드 검증용. 편철 대상은 전부 비전자이므로 이관신청서/관리대장 전달필드로 유지할 필요 없음 |
| 공개구분 | 기록물철 공개구분 집계 |
| 공개제한근거 | 비공개호수 집계 |
| 쪽수 | 편철 100쪽 기준 / 상자 1000매 기준 |
| 과제명 | 표준 단위과제 보조매핑 |
| 과제카드명 | 편철 기준 / 표준 단위과제 1차매핑 |
| 보존기한 | 표준 보존기간 교차검증 |

---

## 6. 문서등록대장에서 검증/참고용으로만 사용할 필드

- 전자비전자구분: 편철 대상이 전부 비전자라는 전제 검증에만 사용. 비전자가 아닌 행이 있으면 업로드 단계에서 경고
- 결재유형: 기존 색인/업무구분에 활용 가능
- 수신(발신)자: 색인목록 등에 활용 가능
- 목록공개여부: 원천정보로 보존하되 표준 '열람구분'으로 직접 자동치환하지 않음

나머지 기안자, 결재권자, 게시여부, 처리상태, 연계유형, 첨부파일여부, 최초발송일자는
현재 표준 기록물철 관리대장 연결에는 필수정보가 아니다.

필요하면 세부색인/원본추적 레이어에서 보존할 수 있지만
이관목록을 복잡하게 만들 필요는 없다.

## 7. 이관신청 단계에서 생성·확정할 필드

문서등록대장 원문을 그대로 전달하는 것이 아니라 편철 후 다음을 확정한다.

- 생산연도 시작/끝
- 기록물철 제목
- 표준 단위과제
- 보존기간
- 기록유형
- 세부유형
- 매체유형
- 수량(권)
- 공개구분
- 비공개호수
- 문서수
- 총 쪽수
- 원본문서번호 목록
- 원본행 참조
- 수동분권/제외/순서수정 이력

---

## 8. 기록물관리 단계에서 생성할 필드

이관신청서에 미리 요구하지 않는다.

- 순번
- 관리번호
- 보존장소
- 등록자
- 서고/서가/열/층
- 위치번호
- 상자번호 / 보존상자
- 기록물상태
- DB등록여부

기관코드는 기관명이 확정되면 표준 기관코드표로 자동산출한다.

기록물철ID는 근거가 없으면 임의 생성하지 않고 공란을 허용한다.

열람구분은 문서등록대장 '목록공개여부'와 같은 개념으로 단정하지 않고 별도 정책을 확정한다.

---

## 9. 최종 데이터 경계

이관신청 자동화 종료 시점에는:

- 기록물의 내용/분류/편철 정보가 완성되어 있어야 한다.
- 기록물관리 자동화가 다시 편철하거나 단위과제를 다시 해석하지 않아야 한다.

기록물관리 자동화는:

- 여러 이관신청서를 취합하고
- 쪽수/보존기간을 이용해 상자를 자동집계하고
- 기관별 관리번호를 부여하고
- 위치/상태를 보완해
- 표준관리대장을 완성한다.

이 경계를 프로젝트의 기본 계약으로 사용한다.


## 12. 비전자 전제 확정

이관신청 자동화에서 편철하는 기록물은 전부 비전자 기록물로 본다.

- `전자비전자구분`은 핵심 연계필드가 아니라 입력 검증필드다.
- 업로드 자료에 전자 기록물이 섞이면 사용자에게 경고한다.
- 일반 비전자 문서는 기본적으로 `문서류 → 일반문서 → 종이`를 제안할 수 있다.
- 다만 비전자 기록물에는 도면·사진·필름·DVD 등도 존재할 수 있으므로 `비전자` 값만으로 매체유형을 일괄 `종이`로 확정하지 않는다.
