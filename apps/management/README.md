# management

## 기록물관리 자동화

여러 기관의 신규 이관자료를 받아 검토·정리하고 보존상자를 구성한 뒤, 기존 표준 기록물관리대장에 통합하는 웹 앱.

예정 기능:
- 신규 이관자료 다중 입력
- 검토 및 수정
- 보존상자 자동 구성/수동 조정
- 스티커/상자표지 생성
- 기존 대장과 통합


## 통합 v0.1 상태

2026-09-21 기준 단일 화면 프로토타입으로 다음 흐름을 연결했다.

```text
이관신청서.xlsx 업로드
→ _handoff current 값 읽기
→ 기관 프로필 적용
→ 상자 자동제외
→ 보존상자 자동배정
→ 철제목 권차 재번호
→ 기존 관리대장 기준 관리번호 부여
→ 최종 데이터 검토
→ 출력 단계
```

### 실제 입력

- 이관신청서 여러 개 업로드 지원
- `_handoff` 시트를 읽고 current 값을 우선 사용
- 동일 packageId/rowId 추적 기반
- 기존 기록물관리대장 업로드 선택 지원
- 기존 대장이 없으면 기관별 10001부터 시작

### 기관 프로필

기관별로 다음 설정을 저장/재사용한다.

- 관리번호 접두어
- 표준대장 유형(학교/직속/기록관)
- 상자제외 기록유형
- 상자제외 철제목 키워드

설정은 '이번 작업에만 적용'과 '기관 기본값으로 저장'을 구분한다.
JSON 내보내기/불러오기로 PC 이동·백업을 지원하는 구조다.

### 상자배정

- 기관 혼합 금지
- 동일 보존기간만 같은 상자
- 최대 8권
- 최대 1000쪽
- 30년/준영구/영구는 보존기간 접두어
- 그 외는 생산연도 접두어
- 자동제외 + 개별 제외/복원
- 수동 새 상자 시작 지원

### 최종 철제목

동일 기관·동일 단위과제의 최종 권수를 기준으로 기존 철제목의 `(총권수-권차)` 부분만 다시 계산한다.
사용자가 수정한 철제목의 본문은 보존한다.
번호 패턴을 찾을 수 없는 제목은 자동으로 덮어쓰지 않고 확인대상으로 둔다.

### 관리번호

기존 관리대장이 있으면 관리번호 숫자부 최대값 다음부터 부여한다.
없으면 10001부터 시작한다.

### 출력

최종 데이터셋은 다음 5개 출력물의 단일 원본이 된다.

1. 기록물철 표지
2. 색인
3. 관리번호 스티커
4. 보존상자 라벨
5. 표준 기록물관리대장

현재 남은 핵심 구현은 GitHub `templates/`에 실제 원본 Excel 템플릿을 등록하고, 최종 데이터를 템플릿 지정 셀/반복영역에 주입하여 완성 Excel을 생성하는 출력 모듈이다.


## 통합 v0.2 진행상태

관리프로그램의 수신 단계가 `_handoff_docs`까지 읽도록 확장되었다.

처리 데이터는 두 계층이다.

- 기록물철 최종데이터: 상자배정, 최종 철제목, 관리번호, 표준관리대장 출력용
- 문서단위 색인데이터: 각 철에 포함된 원본문서의 색인 재생성용

최종 데이터 내보내기 시 두 시트를 함께 생성한다.

1. `기록물철_최종`
2. `색인_원본문서`

다음 구현은 GitHub `templates/`의 원본 Excel 템플릿에 이 두 데이터셋을 주입하여 표지·색인·관리번호 스티커·보존상자 라벨·표준 기록물관리대장을 실제 생성하는 출력 모듈이다.


## 표준대장 실제 출력 테스트 v0.1

학교용 공식 표준양식 `기록물관리대장 서식(학교).xlsx` 자체를 복제하여 최종 관리데이터를 실제 주입하는 테스트를 완료했다.

샘플 기준:
- 기록물철 222권
- 보존상자 25개
- 상자 자동제외 38권
- 기존 관리번호 최대값 `천안버들유-10223` 다음부터 신규 관리번호 부여
- 신규 관리번호 범위 `천안버들유-10224` ~ `천안버들유-10445`
- 천안버들유치원 기관코드 `8151253`

처리 원칙:
- 공식 학교용 템플릿의 헤더/참조시트/유효성검사 구조는 유지
- 신규 `folderId`는 임의 생성하지 않고 공란
- `keepOrgCd/keepOrgNm`과 `creatOrgCd/creatOrgNm`은 학교 기관코드/정식 기관명 사용
- 상자제외 기록물도 관리대장에는 유지하고 상자번호만 공란
- 서고/서가/열/층/위치번호는 실물 배치 이후 입력하므로 공란
- `operReadRangeNm`, `regUser`, 기록물상태, DB등록여부는 정책 확정 전 공란
- 상자번호는 학교용 표준서식의 `excelPresvBoxNm` 열에 기록

출력 파일은 공식 서식의 기본 구조를 유지하며, 메인 시트의 수식 오류 검사에서 오류가 발견되지 않았다.


## 통합 v0.3 — 출력 데이터 연결

실제 v3 이관신청서 구조에 맞춰 수신 파서를 보강했다.

- `_handoff`, `_handoff_docs`의 첫 행을 헤더로 가정하지 않는다.
- 시트 내부에서 `schemaVersion`이 있는 실제 헤더행을 자동 탐지한다.
- 설명행/시스템 메타행이 앞에 있어도 정상 읽는다.

최종 출력 단계에서 같은 최종 데이터셋으로 다음 5종의 주입데이터를 생성한다.

1. 기록물철 표지
2. 색인
3. 관리번호 스티커
4. 보존상자 라벨
5. 표준 기록물관리대장

개별 Excel 또는 `기록물관리_전체출력_주입데이터.xlsx` 한 파일로 내려받을 수 있다.

현재 출력 버튼은 **템플릿에 넣을 값과 배치 구조를 검증하는 단계**이다.
다음 최종 연결에서는 이 값을 GitHub `templates/`의 원본 Excel 파일에 직접 주입해
표지/색인/규정 스티커/상자라벨/표준대장 서식을 그대로 보존한다.

관리번호 스티커 주입데이터는 기존 VBA와 동일하게 1행 5매 배치 구조를 사용한다.
보존상자 라벨 주입데이터는 상자 1개당 최대 8권의 최종 철제목을 포함한다.


## 통합 v0.4 — 표준관리대장 출력 보류

UI 구조와 전체 업무 흐름은 유지하되,
최종 출력 단계에서 **표준 기록물관리대장**은 자리만 남기고 버튼을 비활성화했다.

현재 우선 구현 대상 출력물:
1. 기록물철 표지
2. 색인
3. 관리번호 스티커
4. 보존상자 라벨

표준 기록물관리대장:
- 카드/자리 유지
- '추후 구현' 표시
- 개별 다운로드 비활성화
- '전체 출력데이터 Excel'에서도 제외

레이아웃과 CSS는 현재 구조를 유지하고 기능 연결을 우선한다.


## 통합 v0.5 — GitHub 원본서식 실제 연결

출력 단계에서 더 이상 주입데이터만 생성하지 않고,
GitHub `templates/`의 실제 Excel 원본 4종을 브라우저에서 내려받아 값을 채운 뒤 완성 Excel로 생성한다.

연결 대상:
- `표지(서식).xlsx`
- `색인목록(서식).xlsx`
- `관리번호스티커(서식).xlsx`
- `상자라벨(서식).xlsx`

구현:
- 표지: 원본 A1:F42 블록을 기록물철 수만큼 반복하고 최종 철제목/소제목/연도·보존기간/기관명/관리번호 주입
- 색인: 원본 헤더와 데이터행 서식을 철별로 반복하고 `_handoff_docs`를 주입
- 관리번호 스티커: 원본 규격을 유지하며 1행 5매로 관리번호 주입
- 보존상자 라벨: 원본 한 페이지 3매 구조를 반복하고 상자별 최대 8권의 최종 철제목 주입
- 4종 일괄 출력: ZIP으로 생성
- 표준 기록물관리대장: UI 자리만 유지하고 추후 구현 상태

기존 `주입데이터 확인` 기능은 검증용 보조기능으로 남긴다.

현재 HTML 프로토타입은 GitHub raw 템플릿과 CDN ExcelJS/JSZip을 사용하므로 인터넷 연결이 필요하다.
향후 실제 배포환경에서는 동일 템플릿을 앱 패키지/서버에 함께 배포하여 네트워크 의존성을 제거할 수 있다.


## 통합 v0.6 — 원본 XLSX XML 패치 출력

출력 엔진을 ExcelJS 전체 재저장 방식에서 원본 XLSX 패키지 직접 패치 방식으로 변경했다.

- GitHub `templates/`의 원본 XLSX를 JSZip으로 로드
- `printerSettings1.bin`, 셀 스타일, 병합, 페이지 설정 등 원본 패키지 요소는 유지
- 필요한 `xl/worksheets/sheet1.xml`과 인쇄영역 정의만 수정
- 표지/색인은 원본 행 블록을 복제해 최종 데이터 주입
- 관리번호 스티커는 원본 열/페이지 설정을 유지하고 관리번호 셀만 생성
- 상자라벨은 원본 라벨 블록을 페이지 단위로 복제해 상자 데이터를 주입
- 혹시 남아 있는 externalLinks, 외부 통합문서 관계, #REF 또는 [n] 형식의 레거시 definedName은 출력 시 방어적으로 제거
- 표준 기록물관리대장 출력은 계속 비활성화(추후 구현)
- 기존 레이아웃/CSS와 샘플 테스트 흐름은 유지

목표는 브라우저 생성 XLSX를 Excel에서 열 때 발생하던 “통합 문서의 내용에 문제가 있습니다” 복구 경고를 제거하면서 규정 출력서식의 프린터 설정을 보존하는 것이다.
